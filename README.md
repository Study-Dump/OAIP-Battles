# OAIP Battles

Баттл по C++ для нескольких команд.

`main` — пустой шаблон со скелетом папок атак. Решения и атаки живут только в ветках вида `attack-N`.

## Формат

Одна ветка — одна защита. Ветка `attack-N` означает: команда `N` защищается, все остальные её атакуют.

```text
attack-N/
  README.md                # условие задачи команды N
  solution.cpp             # решение команды N
  attacks/
    teamK/                 # K != N
      0X_описание/
        input.txt
        expected_output.txt
    teamM/
      0X_описание/
        ...
```

- `attacks/teamK/` — тесты команды `K` против команды `N` (`K != N`).
- Внутри — папки `0X_описание`, где `X` — порядковый номер теста.
- В каждом тесте ровно `input.txt` и `expected_output.txt`.
- Свою команду не атакуют: `attacks/teamN` не нужна; если она есть в шаблоне, оставьте пустой.
- Максимум 5 тестов от одной команды на одну защиту.
- CI требует тесты от всех остальных команд. Если кого-то нет — ветка невалидна.
- Пустые папки `attacks/teamK` держатся файлом `.gitkeep`; не удаляйте его, пока не добавите тесты.

`input.txt` — обычный stdin по условию задачи. `expected_output.txt` — точный построчный вывод. Лишние пустые строки и отладочный вывод ломают тест.

## Группам

Каждая команда сдаёт одну папку:

```text
teamN/
  solution.cpp
  attacks/
    teamM/
      0X_описание/
        input.txt
        expected_output.txt
```

где `teamM` — команда, которую атакуют. Преподаватель раскладывает `teamN/attacks/teamM/*` в `attack-M/attacks/teamN/`.

## Преподавателю

1. Для каждой команды используйте ветку `attack-N`.
2. В `attack-N` добавьте `solution.cpp` команды `N`, замените `README.md` условием задачи и разложите атаки остальных команд по `attacks/teamK/`.
3. Сделайте коммит и пуш. CI прогонит решение против всех атак и запишет ревизию в `main`.
4. Повторные пуши — это доработки. Для каждой ветки считаются `solution_rev` и `attack_rev` каждой команды.
5. После всех защит победитель определяется по очкам: 1 тест = 1 очко. Тест прошёл — очко защите, упал — очко автору атаки. Тай-брейк: больше защит «выстоял», меньше ревизий решения, больше ревизий атак.

Ветки не удаляйте до конца: в них хранится история ревизий.
