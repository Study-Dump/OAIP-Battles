# OAIP Battles

Платформа для баттлов по C++: каждая команда защищает своё решение и готовит тесты против решений других команд.

`main` — шаблон и итоговая статистика. Решения и атаки живут в ветках вида `attack-<id>`.

## Настройка

Все общие данные задаются одним файлом `config.json` в корне:

- `title` — название на сайте;
- `repository` — репозиторий в формате `owner/repo`;
- `teams` — список команд: `id` задаёт ветку `attack-<id>`, `group` показывается на сайте;
- `max_tests_per_team` — максимум тестов от одной команды на одну защиту;
- `scoring` — веса `defense`, `attack` и `speed` в итоговом балле.

После правки `config.json` закоммитьте его в `main`: CI и сайт читают конфиг оттуда.

## Ввод и вывод

- `input.txt`: первая строка — `N`; если есть параметр, вторая строка — параметр; далее `N` строк записей через `;`.
- `N = 0` — корректный пустой список: `0` (или `0.00` для стоимости).
- `input.txt` может быть пустым или некорректным — тогда `output.txt` пустой.
- Дробные числа — с точкой; в `output.txt` — 2 знака после точки.
- `solution.cpp` читает `input.txt` и пишет `output.txt`; stdin/stdout не использовать.

## Задачи

### Вариант 1. Склад

Поля: `name;article;price;quantity` — название (до 30), артикул (int), цена (double), количество (int).
Сортировка: цена ↑, затем артикул ↑. Вывести общую стоимость и товары.

- Ввод: `N`, затем `N` строк.
- Вывод: стоимость (2 знака), затем `N` строк `name;article;price;quantity`.

### Вариант 2. Расписание

Поля: `destination;flight;hours;minutes;price` — пункт (до 30), рейс (int), часы (int), минуты (int), цена (double).
Выбрать рейсы до пункта; сортировка: время ↑, затем номер рейса ↑.

- Ввод: `N`, пункт, затем `N` строк.
- Вывод: `M`, затем `M` строк `destination;flight;HH:MM;price`.

### Вариант 3. Библиотека

Поля: `author;title;year;pages` — автор (до 40), название (до 40), год (int), страницы (int).
Выбрать книги после года; сортировка: страницы ↑, затем автор и название.

- Ввод: `N`, год, затем `N` строк.
- Вывод: `M`, затем `M` строк `author;title;year;pages`.

### Вариант 4. Успеваемость

Поля: `full_name;group;gpa;missed` — ФИО (до 40), группа (int), средний балл (double), пропуски (int).
Выбрать `gpa > порога`; сортировка: `gpa` ↓, затем ФИО.

- Ввод: `N`, порог, затем `N` строк.
- Вывод: `M`, затем `M` строк `full_name;group;gpa;missed`.

### Вариант 5. Соревнования

Поля: `full_name;age;points;penalty` — ФИО (до 40), возраст (int), очки (double), штраф (int).
Рейтинг: `points - penalty * коэффициент`. Вывести топ-3.

- Ввод: `N`, коэффициент, затем `N` строк.
- Вывод: `M` (до 3), затем `M` строк `full_name;rating`.
- Сортировка: рейтинг ↓, затем очки ↓, затем ФИО.

В вариантах 2–5 `M` — число строк результата; если подходящих записей нет — `0`.

## Формат

Ветка `attack-<id>` означает: команда `<id>` защищается, все остальные её атакуют.

```text
/attack-<id> (ветка)

  README.md                # условие задачи защищающейся команды
  solution.cpp             # её решение
  attacks/
    teamAuthor/            # автор атак; цель — защищающаяся команда ветки
      0X_описание/
        input.txt
        expected_output.txt
```

- Имя папки `teamAuthor` в `attacks/` — всегда автор атак, а не цель.
- Например, в ветке `attack-1` папка `attacks/team3/` содержит атаки команды `3` на команду `1`.
- Внутри — папки `0X_описание`, где `X` — порядковый номер теста.
- В каждом тесте строго `input.txt` и `expected_output.txt`.
- `input.txt` — обычный stdin по условию задачи. `expected_output.txt` — точный построчный вывод. Лишние пустые строки и отладочный вывод ломают тест.

## Сдача

Каждая команда присылает одну папку `teamX`, где `X` — автор решения и атак:

```text
teamX/
  solution.cpp
  attacks/
    attackY/               # атаки команды X на команду Y
      0X_описание/
        input.txt
        expected_output.txt
```

Внутри `attacks/` папки называются `attack<id>` по цели атак: `attack1` — атаки на команду 1, `attack4` — на команду 4. Это папки цели, не ветки `attack-<id>`. Автор — команда, чья папка `teamX`; поэтому внутри всех тестов в `attackY` автор один и тот же.

Преподаватель раскладывает материалы так:

- `teamX/solution.cpp` → `attack-X/solution.cpp`;
- `teamX/attacks/attackY/*` → `attack-Y/attacks/teamX/*`.

После раскладки папка внутри `attacks/` по-прежнему означает автора атак, а не цель.

## Преподавателю

1. Для каждой команды используйте ветку `attack-<id>`.
2. В `attack-<id>` добавьте `solution.cpp` защищающейся команды, замените `README.md` условием задачи и разложите атаки остальных команд по `attacks/teamAuthor/`.
3. Сделайте коммит и пуш. CI прогонит решение против всех атак и запишет ревизию в `main`.
4. Повторные пуши — это доработки. Для каждой ветки считаются `solution_rev` и `attack_rev` каждой команды.
5. После всех защит победитель определяется по очкам: 1 тест = 1 очко. Тест прошёл — очко защите, упал — очко автору атаки. Тай-брейк: больше защит «выстоял», меньше ревизий решения, больше ревизий атак.
6. Скорость считается как суммарное время / суммарное число строк ввода: так большие тесты не штрафуют защиту только за размер.

Ветки не удаляйте до конца: в них хранится история ревизий.

## Пример сдачи

Команда группы `678103` (`team3`) сдаёт решение и атаки на группы `678101` и `678104`:

```text
team3/                       # группа 678103
  solution.cpp
  attacks/
    attack1/                 # атаки team3 на группу 678101
      01_обычный_ввод/
        input.txt
        expected_output.txt
      02_граничный_случай/
        input.txt
        expected_output.txt
    attack4/                 # атаки team3 на группу 678104
      01_большие_числа/
        input.txt
        expected_output.txt
```

После раскладки эти файлы попадут в ветки так:

```text
attack-3/solution.cpp

attack-1/attacks/team3/01_обычный_ввод/input.txt
attack-1/attacks/team3/01_обычный_ввод/expected_output.txt
attack-1/attacks/team3/02_граничный_случай/input.txt
attack-1/attacks/team3/02_граничный_случай/expected_output.txt

attack-4/attacks/team3/01_большие_числа/input.txt
attack-4/attacks/team3/01_большие_числа/expected_output.txt
```

В ветке `attack-1` папка `attacks/team3` означает, что тесты прислала команда `678103`, а защищается `678101`.
