# OAIP Battles

Платформа для баттлов по C++: каждая команда защищает своё решение и готовит тесты против решений других команд.

`main` — шаблон и итоговая статистика. Решения и атаки живут в ветках вида `attack-<id>`.

## Настройка

Все общие данные задаются одним файлом `config.json` в корне:

- `title` — название на сайте;
- `repository` — репозиторий в формате `owner/repo`;
- `teams` — список команд: `id` задаёт ветку `attack-<id>`, `group` показывается на сайте;
- `max_tests_per_team` — максимум тестов от одной команды на одну защиту;
- `scoring` — веса `defense`, `attack` и `speed` в итоговом балле.

После правки `config.json` закоммитьте его в `main`: CI и сайт читают конфиг оттуда.

## Формат

Ветка `attack-<id>` означает: команда `<id>` защищается, все остальные её атакуют.

```text
/attack-<id> (ветка)

  README.md                # условие задачи защищающейся команды
  solution.cpp             # её решение
  attacks/
    teamK/                 # атаки команды K против защищающейся команды
      0X_описание/
        input.txt
        expected_output.txt
```

- Имя папки `teamK` в `attacks/` — автор атак, а не цель. Цель задаётся веткой.
- Внутри — папки `0X_описание`, где `X` — порядковый номер теста.
- В каждом тесте строго `input.txt` и `expected_output.txt`.
- `input.txt` — обычный stdin по условию задачи. `expected_output.txt` — точный построчный вывод. Лишние пустые строки и отладочный вывод ломают тест.

## Сдача

Каждая команда присылает одну папку `teamX`, где `X` — автор решения и атак:

```text
teamX/
  solution.cpp
  attacks/
    teamY/                 # атаки команды X на команду Y
      0X_описание/
        input.txt
        expected_output.txt
```

Преподаватель раскладывает материалы так:

- `teamX/solution.cpp` → `attack-X/solution.cpp`;
- `teamX/attacks/teamY/*` → `attack-Y/attacks/teamX/*`.

После раскладки папка внутри `attacks/` по-прежнему означает автора атак.

## Преподавателю

1. Для каждой команды используйте ветку `attack-<id>`.
2. В `attack-<id>` добавьте `solution.cpp` защищающейся команды, замените `README.md` условием задачи и разложите атаки остальных команд по `attacks/teamK/`.
3. Сделайте коммит и пуш. CI прогонит решение против всех атак и запишет ревизию в `main`.
4. Повторные пуши — это доработки. Для каждой ветки считаются `solution_rev` и `attack_rev` каждой команды.
5. После всех защит победитель определяется по очкам: 1 тест = 1 очко. Тест прошёл — очко защите, упал — очко автору атаки. Тай-брейк: больше защит «выстоял», меньше ревизий решения, больше ревизий атак.

Ветки не удаляйте до конца: в них хранится история ревизий.

## Пример сдачи

Команда группы `678103` (`team3`) сдаёт решение и атаки на группы `678101` и `678104`:

```text
team3/                       # группа 678103
  solution.cpp
  attacks/
    team1/                   # атаки team3 на группу 678101
      01_обычный_ввод/
        input.txt
        expected_output.txt
      02_граничный_случай/
        input.txt
        expected_output.txt
    team4/                   # атаки team3 на группу 678104
      01_большие_числа/
        input.txt
        expected_output.txt
```

После раскладки эти файлы попадут в ветки так:

```text
attack-3/solution.cpp

attack-1/attacks/team3/01_обычный_ввод/input.txt
attack-1/attacks/team3/01_обычный_ввод/expected_output.txt
attack-1/attacks/team3/02_граничный_случай/input.txt
attack-1/attacks/team3/02_граничный_случай/expected_output.txt

attack-4/attacks/team3/01_большие_числа/input.txt
attack-4/attacks/team3/01_большие_числа/expected_output.txt
```

В ветке `attack-1` папка `attacks/team3` означает, что тесты прислала команда `678103`, а защищается `678101`.
